How the mesh works.

Every Wave node speaks in typed records, not prose. A parent node reads the records and answers a fixed set of questions about the fleet, so a reading can climb from one sensor to a person without anyone retyping it.

Typed assertions. Each record is {kind: assert | escalate, call, action, margin, evidence}, written to the broker’s event log. Nothing downstream has to parse a sentence.

Assert or escalate. A node asserts only when its margin clears its own measured gate. Below the gate it escalates: a record that says where to look, not an answer. That is the right outcome for a read it cannot make.

Six questions, and a seventh for fire. The parent answers T11 to T16 about the fleet. The fire family adds T17: the site state (quiet, watch, elevated, threat, instrument fault, or abstain), the next action, which input decided (mast, detector, controller or neighbours), and what is inconsistent (camera against thermal, a valve open with zero flow, a stale record).

Persistence, then a person. A threat needs two consecutive elevated asserts, or one with the camera above its bar in the same tick. Pre-wet becomes eligible only after every path was tried for ten minutes with no acknowledgement, and it stays an owner-armed rule. An acknowledged escalation hands the site to the person.

A classical rule set answers every clean log by construction. The model earns its place on dirty logs - a missing tick, a duplicated line, records out of order - and on explaining what it saw.
