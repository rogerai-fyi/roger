ROGERAI · integrations

It speaks OpenAI on both sides, so most of this is already done.

There is no plugin to install and no partner to be. The serving side finds the inference server you already run by looking at the ports those servers use. The using side hands your tools a local OpenAI-compatible endpoint, which is the only thing most of them need. Everything named on this page is named because the code goes looking for it, not because anyone agreed to appear here.

§0 / THE WHOLE MIGRATION

Change one line. Gain four things.

- base_url = "https://api.openai.com/v1"
+ base_url = "http://127.0.0.1:4141/v1"   # roger use <model>

That is the whole migration. Your SDK, your tools, your agents - unchanged. What changes is what the line buys you: a dial of models behind one key instead of one vendor, an upstream that sees a station instead of you, a price cap and a signed receipt on every call, and failover you never had to build. The whole trade →

§1 / THE SERVE SIDE

§2 / THE DESK

Agent CLIs you can hand the mic to.

These are wired for you: pick one at the desk and it launches against the band you are tuned to, with a throwaway config that never touches your own. Each was proven end-to-end at the version shown before it was added, and the CLI says so when it finds a version it has not seen.

opencode

Throwaway config; the model pinned on the command line, so a project’s own config cannot re-route it.

proven at 1.17.11

hermes

Throwaway home directory: config, sessions and checkpoints land inside the session and vanish with it.

proven at 0.16.0

aider

Environment and flags only. No files written.

proven at 0.86.2

pi

Throwaway config, like opencode.

proven at 0.84.2

dsh needs setup

Boots a profile rather than a model, so no config we generate can hand it a band. Point it at your station and the desk says how.

seen at 0.1.0-rc.7

claude context only

Runs on its own account and billing. Only the context is handed across - no endpoint, no key, no model - so nothing here is metered.

seen at 2.1.220

codex context only

Your own account and billing; only the context is handed across.

seen at 0.1.0

This list is the CLI's registry, checked by a test. A guest added there and not here, or here and not there, fails the build.

§3 / EVERYTHING ELSE

Two fields, and whatever you already wrote works.

Editors, agents, SDKs, orchestration frameworks, a Discord bot, a cron job. If it can be told a base URL and a key, it is already integrated. There are two ways to give it those, and they reach different things.

The local endpoint

Run roger use <model> where the tool lives. It prints an endpoint on 127.0.0.1 and a session key, signs every request as you, and can reach any band on the market - free stations, paid ones, your own.

OPENAI_BASE_URL=http://127.0.0.1:4141/v1
OPENAI_API_KEY=<the key it printed>

4141 unless it is taken - the CLI prints the port it actually picked.

A grant key

Mint a key and point a remote or headless tool straight at the broker, with no CLI on that machine. A grant is confined to your own nodes - it can never reach another owner's hardware - so this is the shape for "my cloud bot uses the GPU on my desk".

OPENAI_API_BASE=https://broker.rogerai.fm/v1
OPENAI_API_KEY=<grant key>

Both spellings of the base-URL variable are read, because both are in the wild. Streaming works; tool calling and vision work on the stations that pass those capability checks, which the dial shows per model.

§4 / SOMETHING MISSING

If it speaks the API and we do not find it, that is a bug.

A local server on a port the CLI does not probe, or an agent worth wiring at the desk, is worth telling us about. Both lists are short on purpose and grow by being asked.
